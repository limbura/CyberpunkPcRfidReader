# wCopy: чтение числа из карты

Небольшой Python-модуль для PMX-V624-C / wCopy NSR109-HIDIC V806N,
USB VID=2518, PID=6018, HID interface=0.

Задача: MIFARE Classic 1K, блок **1** сектора **0**, ключ **A = FF FF FF FF FF FF**.
Возвращаемое число: **последние 8 байт блока, unsigned big-endian (uint64)**.

## Что передать разработчику

Весь этот каталог. В проект достаточно скопировать `wcopy_reader.py` и установить
зависимость из `requirements.txt`. Модуль не требует первоначальных тестовых скриптов.

- `wcopy_reader.py` — функции чтения, события и классы ошибок.
- `example.py` — однократное чтение с понятными сообщениями.
- `watch_example.py` — непрерывное ожидание прикладывания карт.
- `test_wcopy_reader.py` — автономные тесты протокола и событий.
- `PROTOCOL.md` — описание обмена для переноса в другой язык.

Код рассчитан на Python 3.11+. Исходный аппаратный тест пользователя выполнен
на Windows, Python 3.14.7, hidapi 0.15.0. Рабочая последовательность команд
сохранена. Новая упаковка проверена 17 автономными тестами, включая повтор
пакетов из успешного лога. Новый цикл наблюдения на физическом устройстве
пока не проверен; первым шагом запустите оба примера на ПК со считывателем.

## Запуск на Windows

Распакуйте архив. Откройте терминал в папке, где лежат `.py` файлы.
Закройте nfcPro и другие программы, использующие считыватель.

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe example.py
```

Для событий прикладывания:

```powershell
.\.venv\Scripts\python.exe watch_example.py
```

Прикладывайте по одной карте. Для повторного события с той же картой снимите её
на 1–2 секунды и приложите снова. Завершение — Ctrl+C.

Для подробной диагностики однократного чтения:

```powershell
.\.venv\Scripts\python.exe example.py --debug
```

DEBUG выводит USB-пакеты, включая UID, данные и используемый ключ.
Библиотека сама ничего не печатает и не создаёт файлов.

## Главная функция

```python
from wcopy_reader import read_card_number

number = read_card_number()  # Python int от 0 до 18446744073709551615
```

Карта должна уже находиться на считывателе. Каждый вызов открывает USB,
настраивает считыватель, ищет карту, авторизуется, читает и закрывает USB.
Ноль — обычное успешное значение. Ошибка возвращается через исключение,
а не через специальное число или `None`.

Блок читается целиком (16 байт), затем берутся байты с индексами **8…15**:

```python
number = int.from_bytes(block[8:16], byteorder="big", signed=False)
```

Это двоичное число, не текст и не специальный MIFARE value block.
Для блока `00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 01` результат — **1**.
Первые 8 байт не влияют на результат. В другом языке используйте `uint64` /
`ulong`; при передаче в JavaScript большие uint64 лучше передавать десятичной
строкой, поскольку обычный Number не сохраняет все 64 бита целого.

Если нужны UID и исходные байты:

```python
from wcopy_reader import read_card

card = read_card()
print(card.number)           # последние 8 байт как uint64
print(card.uid.hex(" "))
print(card.block.hex(" "))   # все 16 байт для диагностики
```

`CardData` содержит `uid`, `block`, `atqa`, `sak` и свойство `number`.
Дополнительный метод `card.to_int(offset=8, length=8, byteorder="big")`
позволяет явно задать формат. Такие же параметры доступны у `read_card_number`.

## Обработка ошибок

```python
from wcopy_reader import (
    read_card_number, NoCardError, AuthenticationError,
    CardReadError, RFIDError,
)

try:
    number = read_card_number()
except NoCardError:
    print("Приложите карту")
except AuthenticationError as error:
    print("Авторизация не прошла:", error.status)
except CardReadError as error:
    print("Не удалось прочитать блок:", error.status)
except RFIDError as error:
    print(error.code, error.stage, str(error))
else:
    print("Получено число:", number)
```

Все ожидаемые ошибки устройства наследуются от `RFIDError`:

| Исключение | code | Значение |
|---|---|---|
| `DependencyError` | `DEPENDENCY_ERROR` | Не установлен/не загрузился hidapi |
| `ReaderNotFoundError` | `READER_NOT_FOUND` | Нужного USB-устройства нет |
| `MultipleReadersError` | `MULTIPLE_READERS` | Нужно выбрать один из нескольких считывателей |
| `ReaderOpenError` | `READER_OPEN_ERROR` | HID не открылся: занят, отключён, нет доступа и т. п. |
| `USBError` | `USB_ERROR` | Сбой USB, в том числе неполная передача |
| `ReaderTimeoutError` | `READER_TIMEOUT` | Нет ответа в срок; это не доказательство отсутствия карты |
| `ProtocolError` | `PROTOCOL_ERROR` | Неверная контрольная сумма, номер, структура или длина ответа |
| `ReaderCommandError` | `READER_COMMAND_ERROR` | Устройство отклонило команду / вернуло ошибку APDU |
| `NoCardError` | `NO_CARD` | Считыватель явно сообщил, что карта не обнаружена |
| `UnsupportedCardError` | `UNSUPPORTED_CARD` | Неожиданные SAK или длина UID |
| `AuthenticationError` | `AUTHENTICATION_FAILED` | Сбой авторизации блока |
| `CardReadError` | `CARD_READ_FAILED` | Сбой чтения после авторизации |

Поля исключения: `code` — категория, `stage` — этап,
`status` — сырой числовой статус либо `None`, `response` — ответ либо `None`.
Текст сообщения предназначен человеку: ветвить логику нужно по классу или `code`.
`stage`: dependency, enumerate, open, initialize, rf_off, rf_on, configure,
poll, authenticate, read, close.

Неправильный ключ — одна из причин `AuthenticationError`, но такую же ошибку
может вызвать снятая/нестабильно лежащая карта. Модуль не утверждает,
что точно определил неверный ключ. Ошибки APDU и структуры ответа могут
возникать на любом этапе: последний `except RFIDError` обязателен для полного
покрытия ожидаемых сбоев оборудования.

Ошибки аргументов API вызывают `ValueError`. Ошибки программы вызывающего кода
не маскируются под ошибки RFID.

## Событие «новая карта приложена»

`watch_cards()` — блокирующий генератор событий. Его можно использовать как
источник событий приложения:

```python
from wcopy_reader import watch_cards, CardPresented

for event in watch_cards():
    if isinstance(event, CardPresented):
        on_new_card(event.number, event.uid)  # ваша функция
    else:
        on_reader_error(event.error)         # ваша функция; объект RFIDError
```

`on_new_card` и `on_reader_error` здесь — функции вашего приложения, их нужно
определить. Готовый запускаемый вариант — `watch_example.py`.

Правила:

1. `CardPresented` выдаётся после успешного чтения. Поля: `.number`, `.uid`,
   `.card` (полный `CardData`).
2. Пока успешно читается тот же UID, повторных событий нет. Изменение числа
   на удерживаемой карте само по себе нового события не вызывает.
3. Другой UID вызывает событие сразу после успешного чтения, даже если
   промежуточное отсутствие карты не было замечено.
4. Два последовательных ответа «карты нет» снимают запоминание UID. После
   этого та же карта снова вызывает событие. Порог: `removal_checks=2`.
5. Тайм-аут, ошибка USB или авторизации не считаются снятием карты.
6. Ошибки передаются как `CardError(error=...)`. Повторы одной ошибки
   (одинаковые code/stage/status) подряд подавляются. Успешное чтение или
   ответ «нет карты» сбрасывают подавление ошибок. «Нет карты» в режиме
   наблюдения — нормальное ожидание и отдельного события не создаёт.

Это программный опрос, а не аппаратное уведомление. Короткое снятие между
опросами может быть не замечено. Карты с одинаковым UID не различаются.
Карту, которую нельзя прочитать, программа сообщает как ошибку, а не как
`CardPresented`. Наблюдение повторяет попытки после ошибок до остановки.

`interval=0.25` — пауза **после** чтения/обработки события, а не гарантированный
период опроса. Полный период включает все команды и время обработчика.
Если неподвижная карта даёт ложные повторные события, увеличьте
`removal_checks` и проверьте расположение карты.

### Подключение к GUI / фоновому потоку

Чтение блокирующее: не запускайте цикл в потоке интерфейса.
Передавайте события в GUI через очередь или механизм сигналов его фреймворка.
Пример основы:

```python
import queue
import threading
from wcopy_reader import watch_cards

stop = threading.Event()
events = queue.Queue()

def worker():
    for event in watch_cards(stop=stop):
        events.put(event)

thread = threading.Thread(target=worker)
thread.start()
# GUI забирает events.get_nowait() и обрабатывает события в своём потоке.
# При завершении приложения:
stop.set()
thread.join()  # ожидать вне критичного обработчика GUI
```

`stop.set()` завершает цикл после текущей операции и обработки выданного
события; прерывания USB-команды посередине нет. `timeout_ms=2500` ограничивает
ожидание **одного ответа**, а не всего вызова; открытие USB, очередь блокировки
и обработчик событий в этот срок не входят.

Вызовы чтения сериализуются внутри одного процесса. Используйте один цикл
наблюдения на считыватель; другие приложения одновременно его использовать
не должны. Межпроцессной блокировки модуль не создаёт.

Если считывателей несколько:

```python
from wcopy_reader import list_readers, read_card_number

readers = list_readers()
for item in readers:
    print(item.product, item.path)
# Выберите нужный путь, затем передайте path=selected_path
# в read_card_number, read_card или watch_cards.
```

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest -v
```

17 тестов: точные запросы/ответы из реального лога; выбор последних 8 байт;
0, максимум uint64 и данные с окончанием 90 00; отсутствие карты;
авторизация, чтение, USB, тайм-аут, повреждённые пакеты; удержание карты,
повторное прикладывание, замена UID и подавление повторных ошибок.

Для проверки на устройстве используйте карту с известным числом, затем:
уберите карту, повторно приложите её, замените другой картой, отключите и
подключите USB. Для ошибки авторизации можно приложить свою тестовую карту
с другим ключом. Снятие карты между командами не всегда воспроизводит одну
и ту же категорию ошибки — она зависит от этапа сбоя.
