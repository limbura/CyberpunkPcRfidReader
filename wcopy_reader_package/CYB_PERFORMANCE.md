# Диагностика скорости Cyb

С версии **1.8.0** обычное чтение Cyb использует один запрос
0x6C(start=0, count=2) без 0x69. По аппаратной проверке двух карт
получены время 45,7 и 43,5 мс, правильный 4-байтовый UID из блока 0
и корректный блок 1. BCC производителя прошёл проверку. Пустая антенна
на тестовом чтении блока 0 дала mask=0 за ~147 мс.
Фактическое время нового опроса зависит также от 0x51, USB и пауз
Master Manager. В записи Cyb оставлена **старая процедура**
0x69 → 0x6C(1,1) → 0x6A → 0x69 → 0x6C(1,1).
Обычный пользовательский API и код wCopy не меняются.
Для 4-байтового UID ожидаем BCC в manufacturer block0[4];
другие форматы в быстром режиме отклоняются.
ATQA/SAK в CardData при быстром Cyb — нулевые маркеры отсутствия
радиочастотных данных, а не измеренные значения.

В старых аппаратных журналах (до постоянного управления с ПК) запрос 0x69
занимал 437–735 мс, медиана 712 мс (10 запросов). Чтение блока 0x6C:
18–20 мс, медиана 18,5 мс (4 запроса). Подтверждение управления 0x51:
13–156 мс, медиана 18 мс (5 запросов).
Источник: cyb_20261112_161459_562763.log.
Это не измерения текущей версии и не точное время от прикладывания карты.

До 1.7.1 обычное чтение Cyb выполняло два запроса 0x69, а в
1.7.1 — один. Теперь поиск заменён однокомандным чтением 0x6C(0,2)
в обычном read_card(). Для записи старые проверки UID сохранены:
перед записью и после неё выполняются 0x69 и 0x6C(1,1).
Отрицательная маска 0x6C не различает отсутствие карты,
неподходящий ключ и ошибку RF: mask=0 трактуется как NoCardError
лишь для быстрого фонового опроса; частичные маски — CardReadError.
Команда 0x62 является процедурой Darkside и для опроса не используется.

## Запуск

Закройте Master Manager и Cyb_Nfctool. В VSCode запустите
`wcopy_reader_package/tests_and_other/cyb_speed_diagnostics.py`, либо из корня:

```console
python wcopy_reader_package/tests_and_other/cyb_speed_diagnostics.py
```

По запросу сначала уберите карту, затем приложите одну карту и оставьте её
неподвижно. Скрипт выполнит по пять чтений в каждом режиме:

| Режим | USB | Подтверждение 51=01 |
| --- | --- | --- |
| A | Открытие/закрытие при каждом чтении | Каждый раз |
| B | Открыто на всю серию | Каждый раз |
| C | Открыто на всю серию | Только перед первым чтением |

Во всех режимах используется процедура установленной версии библиотеки. Записи на карту и команд
индикации нет. После завершения скрипт пытается вернуть автономный режим;
результат отражён в cleanup_ok. Прошивка может подать собственный сигнал.
При ошибке серия останавливается, ошибка сохраняется в отчёте.

Пришлите созданные `.json` и `.log` из `wcopy_reader_package/diagnostics_logs`.
JSON содержит время каждой операции и USB-вызовов. Вложенные времена нельзя
складывать: время USB-чтения уже входит во время команды и полное время.
Для B/C открытие USB записано отдельно как setup; первая операция включает
первую инициализацию. Сравнивать нужно также последующие операции.

По умолчанию timeout=2500 мс позволяет измерить медленный ответ, не обрывая его
на 750 мс. Это предел ожидания, а не обязательная задержка. Настройки библиотеки
и Master Manager скрипт не меняет. Для отдельного сравнения с лимитом приложения:

```console
python wcopy_reader_package/tests_and_other/cyb_speed_diagnostics.py --timeout-ms 750
```

Уменьшение таймаута само по себе не ускоряет успешный ответ. По результатам
можно сравнить скорость разных версий библиотеки.


## Изолированное исследование команды 0x69

Для проверки собственно команды `CMD_HF_MIFARE_INFO (0x69)` используйте
`tests_and_other/cyb_69_diagnostics.py`. Это **отдельная диагностика**,
без Master Manager, без чтения блока `0x6C`, без записи `0x6A`
и без команд индикации `0x55`. Отправляются только `0x51`
(включить/выключить управление ПК) и `0x69` (опрос UID).

Запуск из корня репозитория:

```powershell
python wcopy_reader_package/tests_and_other/cyb_69_diagnostics.py
```

Или откройте файл в VS Code и выберите **Run Python File** с окружением,
где установлен `hidapi`. Сначала завершите Master Manager и штатную
программу Cyb. Скрипт попросит убрать карты и нажать Enter, затем
приложить одну MIFARE Classic и удерживать неподвижно.

По умолчанию запускается **по 30 опросов в каждом из трёх режимов**
для двух условий (без карты / с картой) с паузой 0,1 секунды.
Итого до 180 вызовов `0x69`.

| Режим | USB-дескриптор | Управление ПК `51=01` |
| --- | --- | --- |
| `reopen` | Каждый раз открывается и закрывается | Каждый опрос |
| `reassert` | Открыт на всю серию | Каждый опрос |
| `once` | Открыт на всю серию | Только первый опрос |

Дополнительные паузы для сравнения:

```powershell
python wcopy_reader_package/tests_and_other/cyb_69_diagnostics.py --samples 30 --intervals 0,0.1,0.5
```

Также доступны `--modes once` и `--timeout-ms 1500`.
Интервалы 0, 0.1 и 0.5 — секунды между **завершением и началом**
следующего запроса, а не период таймера.

Создаются файлы `diagnostics_logs/cyb_69_*.csv`, `*.json`, `*.log`:

- CSV — строка на один запрос, время `0x69`, ожидания USB,
  очистки, передачи и других накладных расходов.
- JSON — те же данные, вложенные замеры и сводка по медиане/P90/ошибкам.
- LOG — ошибки самого диагностического скрипта; в норме может быть пуст.

Замеры вложенные: `poll_69_ms` уже включает `poll_drain_ms`,
`poll_usb_write_ms` и `poll_usb_read_ms`. Последнее показывает время,
проведённое в вызовах USB-чтения **после** очистки буфера. Оно не
раскрывает внутренние стадии работы прошивки. В отчетах не записываются
UID или содержимое карты. Скрипт использует приватные методы библиотеки
и предназначен только для диагностики текущей ветки.

В конце выполняется попытка вернуть устройство в автономный режим:
`cleanup_ok` в JSON. Если `false`, переподключите USB перед
использованием штатного ПО. Не выдёргивайте USB во время измерения
без необходимости. При ошибке текущая серия останавливается;
частичные CSV и JSON остаются на диске.

## Эксперимент прямого чтения 0x6C без предварительного 0x69

Скрипт: `tests_and_other/cyb_6c_direct_diagnostics.py`.
Он не меняет библиотеку или Master Manager. Выполняет только:
`0x51` (управление), `0x6C` (прочитать блок 1), `0x69`
(получить UID **только в контрольных точках**).
Запись карты `0x6A` и индикация `0x55` не отправляются.

**Нужны две разные игровые карты A и B с различающимися данными блока 1.**
Закройте Master Manager и другие программы, использующие Cyb.
Для чистого старта переподключите считыватель по USB, положите карту A
и запустите из корня репозитория:

```powershell
python wcopy_reader_package/tests_and_other/cyb_6c_direct_diagnostics.py
```

Или используйте кнопку **Run Python File** в VS Code.
Следуйте инструкциям на экране: A (прямое чтение до первой `0x69`),
контроль A, удержание A, снятие A, B (без `0x69` после снятия A),
контроль B, возврат A (без `0x69` после B), финальный контроль A.
**Не перекладывайте карту до приглашения скрипта.**
По умолчанию выполняется по 8 прямых чтений в каждой фазе с паузой 100 мс.

Результаты записываются в `diagnostics_logs/cyb_6c_*.csv`,
`cyb_6c_*.json`, `cyb_6c_*.log`.
JSON содержит время каждой команды, контрольные сравнения и предупреждения,
CSV удобен для статистики; LOG может быть пустым. UID и блоки **не сохраняются**:
вместо них — анонимные метки, рассчитанные по секретному ключу только
для этого запуска (метки из разных запусков сравнивать нельзя).

**Ограничения:** `0x6C` не возвращает UID. Даже если она читает данные
без `0x69`, подмена карты с тем же содержимым блока останется неотличима.
Отрицательный результат чтения может быть вызван отсутствием карты,
ошибкой аутентификации или RF — это **не доказательство снятия**.
При тайм-ауте или ошибке протокола эксперимент прекращается во избежание
сопоставления запоздавших ответов с новыми командами; частичные результаты
сохраняются. При завершении скрипт пытается вернуть автономный режим
(`cleanup_ok` в JSON). Если это не удалось — переподключите USB.

**Критерий успеха:** прямое `0x6C` до любого `0x69` находит A;
после снятия не выдаёт успешное чтение; после замены на B выдаёт именно
данные B; возврат A тоже определяется правильно. Даже тогда для
эквивалентности текущему API потребуется отдельно решить получение UID
и защиту от разных карт с одинаковым блоком.


## Диагностика: UID из блока 0 через 0x6C

**Только эксперимент.** Основной `read_card()` по-прежнему использует
`0x69`, а рабочие операции записи не меняются.

Скрипт: `tests_and_other/cyb_6c_uid_diagnostics.py`.
Команды: только `0x51` (управление с ПК), `0x6C` (чтение),
`0x69` (контрольный UID). **Команд записи нет.**
Задача: прочитать блок производителя (сектор 0, блок 0)
*до любого `0x69`*, извлечь из его начала UID и сравнить с
ответом обычного обнаружения карты.

Запуск из корня репозитория:

```powershell
python wcopy_reader_package/tests_and_other/cyb_6c_uid_diagnostics.py
```

Нужны две **разные** карты MIFARE Classic (для минимального теста одной карты:
`--cards 1`). Завершите Master Manager и другие программы для считывателя.
По просьбе скрипта переподключите USB, приложите A и нажмите Enter. Сначала
будет `0x6C(start=0,count=1)`, затем эталонная `0x69`; следом
`0x6C(start=0,count=2)` — чтение двух блоков одной командой;
затем отдельно `0x6C(start=1,count=1)` для проверки второго блока.
При двух картах проверяются пустая антенна, B до `0x69` для B и
возврат A.

В консоли показываются полученные UID в шестнадцатеричном виде
и результат сравнения. Файлы `diagnostics_logs/cyb_6c_uid_*.csv`,
`*.json`, `*.log` **не сохраняют исходные UID и содержимое блоков**.
Они содержат измеренные времена, маски успешности, сравнения и
анонимизированные отпечатки, действительные только в пределах запуска.
`.log` без ошибок может быть пуст.

Ожидаемый ответ на один блок: 4-байтовая маска `00000001` и 16 байт.
Для двух блоков ожидается маска `00000003` и 32 байта. Это
гипотеза, требующая подтверждения на устройстве. Для карт с UID длиной
4 байта сравниваем `block0[0:4]` с UID из `0x69` и отдельно
проверяем BCC `block0[4]`. Для 7 байт сравниваем первые 7 байт,
без предположений о BCC. Другие длины не интерпретируются.

Если любая команда вернула ошибку обмена/тайм-аут, диагностика
останавливается (запоздавшие ответы могут испортить последующие сравнения),
но частичный отчёт сохраняется. После эксперимента вызывается
`close_readers`, поле `cleanup_ok` в JSON указывает результат.
Если вернулось False — переподключите USB.

Даже при успешном совпадении UID у двух карт не доказана
работоспособность метода для нестандартных UID, других ключей или
смены карты *во время* чтения. Сначала изучите отчёты, прежде чем менять
производственную библиотеку.
