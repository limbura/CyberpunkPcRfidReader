# wCopy / Cyb: чтение и запись — 1.7.0

Библиотека автоматически выбирает протокол подключённого считывателя.
Импорт `wcopy_reader`, существующие функции, аргументы и типы результатов сохранены.

| Семейство | USB VID:PID | Состояние поддержки |
|---|---|---|
| PMX-V624-C / wCopy NSR109-HIDIC V806N (nfcPro) | `2518:6018` | Прежний аппаратно проверенный протокол |
| Cyb_Nfctool | `0483:4300`, `0483:4343` | Чтение/запись проверены на `0483:4343`; звук и красный LED поддерживаются |

Cyb дополнительно проверяется по строкам производителя, продукта и серийного номера,
как в оригинальном приложении. Неизвестным HID-устройствам команды не отправляются.
Если подключены два поддерживаемых считывателя, сохраняется `MultipleReadersError`:
выберите `path` из `list_readers()` либо отключите лишний. При одном устройстве
приложению не нужно выбирать модель или передавать новые аргументы.

### Автоматическая индикация и новое прикладывание

По умолчанию `read_card()`, `read_card_number()` и `write_card_number()` сами
управляют индикацией; приложение не должно дополнительно вызывать LED/звук.

| Событие | Cyb | wCopy |
|---|---|---|
| Новая успешно прочитанная карта | Один короткий писк t=5 | Только обновление штатного LED, без команды писка |
| Повторный опрос удерживаемой карты | Без команд индикации | Обновление LED |
| Ответ «карты нет» | Без команд индикации | Обновление LED |
| Запись с проверкой всего блока и UID | Два коротких писка `01 01 02 00` | LED, затем один писк t=10 |

Внутренние чтения при записи без сигналов. Сбой автоматической индикации
журналируется и не меняет результат операции; повторная попытка разрешается
через секунду при следующем подходящем событии. Запись не повторяется из-за звука.
Cyb сохраняет управление с ПК между операциями: после первого захвата автономный
двойной писк подавляется. USB-дескриптор закрывается после каждой операции;
перед каждым read/write режим заново подтверждается командой 51=01.
При штатном завершении вызовите `close_readers()` после остановки опроса;
он также зарегистрирован через atexit. При аварийном убийстве процесса возврат
не гарантирован — переподключите USB. Не запускайте одновременно другое ПО считывателя.

Для сравнения с прежним режимом: `set_persistent_host_control(False)` сразу
пытается вернуть автономный режим и далее освобождает Cyb после каждой операции.
Обратное включение — `set_persistent_host_control(True)`, со следующей операции.
Это отдельно от auto_feedback: его отключение не возвращает автономный режим.
`close_readers()` возвращает bool; ошибки освобождения журналируются и не отменяют
записанные данные. Повторный вызов допустим. Старый wCopy не меняет режим.

[План аппаратной проверки надёжности](wcopy_reader_package/PERSISTENT_CONTROL_CHECKLIST.md).

`CardData.is_new` отмечает первое успешное чтение нового прикладывания.
`CardData.presentation_id` — уникальный в процессе номер прикладывания, стабильный
при удержании карты. Смена UID или два подряд ответа «карты нет» разрешают новое
прикладывание. Ошибка связи прерывает счётчик отсутствия, но не считается снятием.
Состояние хранится отдельно для каждого HID-пути, без фонового опроса внутри библиотеки.
`is_card_removed(path=...)` проверяет уже накопленные два ответа «карты нет»;
без path используется последний выбранный считыватель. Сам вызов USB не опрашивает.
Успешная запись также отмечает карту присутствующей: следующий опрос не пищит заново.

Чтобы отключить автоматическую индикацию, передайте `auto_feedback=False` в каждый
вызов чтения/записи или в `watch_cards()`. Отслеживание прикладываний сохраняется,
штатный звук прошивки не отключается. Ручные `beep`, `set_led`,
`set_reader_feedback` остаются доступны независимо от этого параметра.

```python
card = read_card()                         # Индикация автоматически
print(card.number, card.is_new, card.presentation_id)
number = write_card_number(555)            # Сигнал только после проверки
card = read_card(auto_feedback=False)      # Без автоматических команд LED/звука
```

### Первая проверка Cyb

Закройте Cyb_Nfctool/nfcPro. Из папки `wcopy_reader_package`, после установки зависимостей:

```powershell
.\.venv\Scripts\python.exe .\tests_and_other\cyb_diagnostics.py
```

Скрипт можно запустить кнопкой Run Python File в VS Code. Он предлагает убрать карту,
приложить её, повторно прочитать и убрать. **По умолчанию записи нет.**
Файлы `.json` и `.log` появятся в `wcopy_reader_package/diagnostics_logs`.
Они содержат USB-метаданные, UID, содержимое блока и обмен с устройством.
Первый аппаратный прогон подтвердил определение `0483:4343`, интерфейс 1.
Версия 1.5.1 учитывает дополнение коротких USB-записей в HIDAPI на Windows
и выводит фактический результат `write` в DEBUG-журнал. Следующие прогоны подтвердили чтение, отсутствие карты, запись числа 555
с проверкой UID/всего блока и возврат в автономный режим на `0483:4343`.
Если чтение подтверждено, отдельная проверка записи тестовой карты:

```powershell
.\.venv\Scripts\python.exe .\tests_and_other\cyb_diagnostics.py --write 555
```

Скрипт запросит отдельное подтверждение и проверит исходные UID/блок перед записью.
Cyb читает и пишет только блок 1 обычными командами с известными ключами FF…FF;
поиск ключей, клонирование UID, форматирование и обновление прошивки не используются.

**Индикация Cyb:** `beep(t=5, count=1)` отправляет `01 01 01 00`.
Длительность равна `max(1, t-4)`: t=6 → 02, t=7 → 03. Интервал всегда 01.
`count` — положительное целое; Cyb ограничивает его 255, старый wCopy всегда
подаёт один сигнал. `set_led("red")` и `set_led("green")` отправляют `00 01 01 00`
(включить красный LED без звука); `set_led("off")` — `00 00 00 00`.
`set_reader_feedback(color, beep=True, count=1)` сначала устанавливает LED,
потом подаёт звук: звук может снова включить LED даже при color="off".
Cyb не подтверждает команды индикации: одиночные вызовы возвращают `b""`,
комбинированный — кортеж пустых байтов. Ошибки связи с выбранным Cyb только
журналируются; аргументы и неоднозначный/отсутствующий считыватель всё ещё проверяются.
Ручная индикация по умолчанию не включает управление с ПК; `initialize=True` включает
его с сохранением до close_readers() при включённом постоянном режиме.
Ошибки чтения и записи по-прежнему передаются приложению.

### Ручной ввод байтов индикации Cyb

Запустите `wcopy_reader_package/tests_and_other/cyb_feedback_manual.py` в VS Code.
Введите **четыре байта HEX**, например `01 01 01 00`, и нажмите Enter: команда
индикации `0x55` отправится один раз. Заголовок, длина, контрольная сумма и HID
report ID формируются автоматически. Доступны все значения `00..FF` каждого байта.
Для десятичных чисел используйте `dec 1 3 1 0`.

После отправки скрипт спрашивает наблюдение о звуке и LED. Все команды, ответы и
наблюдения сохраняются по мере работы в `diagnostics_logs/cyb_manual_*.json` и `.log`.
Пустая строка ничего не отправляет. `on` включает управление с ПК, `off` возвращает
автономный режим, `q` завершает работу. По умолчанию `on` не выполняется: проверенные
звуковые команды действуют и без него. После включённого `on` при выходе выполняется
возврат в автономный режим. При ошибке USB скрипт останавливается без повторной отправки.
Карты не опрашиваются, не читаются и не записываются. Если эксперимент вызовет долгий
сигнал, отключите USB; отдельная команда остановки пока не установлена.

### Исследование звука и LED Cyb

По наблюдению пользователя, без команд ПК считыватель сам издаёт два сигнала при
прикладывании карты; LED постоянно красный. Включение и выключение красного LED подтверждено ручными опытами.
Отдельный диагностический скрипт запускается кнопкой VS Code:

```text
wcopy_reader_package/tests_and_other/cyb_feedback_diagnostics.py
```

Закройте другие программы, переподключите USB, запишите в ответ на первый вопрос
поведение при прикладывании/снятии карты. Затем **уберите карту** и выберите пункт 1.
Он проверяет два режима из оригинального приложения и спрашивает, что реально
слышно и видно после каждой команды. На первом прогоне достаточно пункта 1,
затем 0 для выхода. Пришлите `.json` и `.log` с префиксом `cyb_feedback_` из
`diagnostics_logs`. Ответы на вопросы входят в JSON.

Пункт 2 повторяет два режима без включения управления с ПК; пункт 3 меняет малые
значения параметров для исследования длительности/числа сигналов. Их можно оставить
до анализа первого прогона. Скрипт отправляет только команды `0x51` и `0x55`;
карты не опрашивает, не читает и не записывает. Вызовы индикации оригинального
приложения не ждут ответа: отсутствие USB-ответа здесь не считается провалом.
Четвёртый байт команды в EXE явно не инициализирован; в тесте он установлен в 0.
Функции `beep`/`set_led` основной библиотеки используют результаты ручных опытов.

Подробности и границы подтверждённого: [CYB_PROTOCOL.md](wcopy_reader_package/CYB_PROTOCOL.md).
Описания аппаратных масок LED и длительности писка ниже относятся к **wCopy**.
Примеры ручной индикации используют `auto_feedback=False`, чтобы не дублировать автоматические сигналы.

Номер версии задаётся в [`wcopy_reader_package/wcopy_reader.py`](wcopy_reader_package/wcopy_reader.py),
в переменной `__version__`. При выпуске новой версии обновите также заголовок этого README.
Имя папки `wcopy_reader_package` от версии не зависит.

Для PMX-V624-C / wCopy NSR109-HIDIC V806N, USB 2518:6018, HID interface 0.
Python 3.11+, зависимость `hidapi` из [requirements.txt](wcopy_reader_package/requirements.txt).
MIFARE Classic: **блок 1 сектора 0**, **ключ A = FF FF FF FF FF FF**.
ID по умолчанию — **байты 8…15**, беззнаковое 64-битное число **big-endian**.

## Быстрый запуск на Windows

Клонируйте репозиторий или распакуйте его архив. README находится в корне репозитория,
а библиотека, зависимости, примеры и тесты — в папке `wcopy_reader_package`.

| Путь от корня репозитория | Назначение |
|---|---|
| `wcopy_reader_package/wcopy_reader.py` | Модуль библиотеки |
| `wcopy_reader_package/requirements.txt` | Зависимости библиотеки |
| `wcopy_reader_package/examples/` | Примеры чтения, записи и наблюдения |
| `wcopy_reader_package/tests_and_other/` | Автотесты и ручная диагностика |

| `original_exe/` | Программы производителя; библиотека их не запускает |

Откройте терминал в корне репозитория и перейдите в папку библиотеки:

```powershell
cd .\wcopy_reader_package
```

**Все команды ниже выполняются из этой папки.** Если терминал уже открыт в ней,
повторять `cd` не нужно. Для обновления существующего клона используйте Pull;
локальное окружение `.venv` в репозиторий не входит.
Закройте nfcPro, Cyb_Nfctool и другие приложения, работающие со считывателем.
При первом запуске в новой папке:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Команда `py -3` должна выбирать Python 3.11 или новее. После обновления библиотеки
повторите установку из `requirements.txt`, используя существующее окружение.
Запускайте именно Python из окружения, куда установили hidapi:

.\.venv\Scripts\python.exe .\examples\write_example.py
.\.venv\Scripts\python.exe .\examples\watch_example.py

```powershell
.\.venv\Scripts\python.exe .\examples\write_example.py 555
```

## Принцип: приложение решает, когда показывать свет и подавать звук

Обычные `read_card()`, `read_card_number()`, `write_card_number()` и
`watch_cards()` **не отправляют команды LED или писка**. Они всё ещё настраивают
радиополе для работы с картой; собственная индикация прошивки возможна.

Отдельные функции:

```python
from wcopy_reader import set_led, beep

set_led("red")     # маска «красный»; прямой цвет не гарантируется
set_led("green")   # маска «зелёный»; важен сам вызов после опроса
set_led("off")     # маска «выключить»; реальное выключение не подтверждено
beep()             # один сигнал, T=5 по умолчанию
beep(t=10)         # более длинный сигнал, как в примере записи
```

Вызовы открывают и закрывают HID автоматически. Каждый возвращает сырой ответ
`bytes`; ошибки передаются через `RFIDError` и его подклассы. Доступны параметры
`path` и `timeout_ms`, как у чтения, а также `initialize=False`.
После read/write дополнительный INIT не требуется. Для самостоятельного вызова
можно передать `initialize=True`; это выполняет только INIT, не поиск карты.

**Команды LED необходимо сохранять для штатной индикации при опросе.**
В аппаратных тестах NSR109-HIDIC V806N от 11.10.2026 режимы red, green и off
вели себя одинаково: без карты красный, с картой зелёный и один штатный писк.
Если после чтения не отправлять команду индикации, LED остаётся красным и
писка нет. Повторное открытие/закрытие HID и дополнительная пауза около 52 мс
не заменяют команду. В ручном режиме (`auto_feedback=False`) повторяйте set_led после КАЖДОГО успешного опроса
и ответа «нет карты», как в watch_example. Минимальная необходимая частота
ещё не исследована; сохраняем проверенную последовательность.

**Напрямую задать цвет или выключить LED этими функциями не удалось.**
Одиночные команды после INIT или чтения, в том же или новом HID-сеансе,
видимого переключения не дали. Команда red не заставляет LED оставаться
красным при карте, off не гарантирует выключение. Названия сохранены для
совместимости и дальнейшего исследования. Механизм влияния на штатную
индикацию пока неизвестен. Ответ 90 01 не подтверждает физический цвет.
Опыт без INIT завершился ошибкой USB и не доказывает отсутствие поддержки.

Писк подтверждён отдельно: T=1 очень короткий; T=3 длиннее; T=5 и T=10 близки
к штатному. В nfcPro найдены обычные вызовы с T=5 и отдельный с T=10.
На этих опытах изменения LED во время писка не замечены; независимость
для всех режимов не гарантируется. В watch дополнительный beep не нужен:
штатный звук уже работает благодаря командам индикации. После записи LED-команды
не дали звука; там используем отдельный beep(t=10) после обратной проверки.

Параметр `t` у `beep()` — **целое число 1..255, сырое поле T, не миллисекунды**.
По умолчанию t=5. Аппаратно проверены 1, 3, 5, 10; рост времени USB-ответа
составил примерно 10–11 мс на единицу T, но это не измерение звука.
Неверное значение (включая bool и дробное число) даёт ValueError до открытия USB.
Для больших T при необходимости увеличьте timeout_ms, например до 5000.

## Настройки в примерах

Настройки стоят в начале каждого файла:

| Пример | Настройки по умолчанию | Поведение |
|---|---|---|
| `read_example.py` | `SUCCESS_LED = "green"`, `SUCCESS_BEEP = False` | После чтения команда индикации с маской green (не гарантия цвета) |
| `write_example.py` | `SUCCESS_LED = None`, `SUCCESS_BEEP = True`, `SUCCESS_BEEP_T = 10` | После подтверждённой записи отдельный писк с T=10 |
| `watch_example.py` | `USE_LED = True`, `IDLE_LED = "red"`, `PRESENT_LED = "green"`, `EXTRA_BEEP = False` | Прежний проверенный режим с командами LED без дополнительного писка |

Для SUCCESS_LED значение None означает «не отправлять команду индикации».
Можно задать `"red"`, `"green"` или `"off"`, учитывая ограничения выше.
SUCCESS_BEEP_T в write_example определяет значение T отдельного писка.

Во всех примерах есть `--no-feedback`, отключающий команды индикации приложения.
В watch на проверенном устройстве это также лишает штатного цвета/писка при опросе.
У write_example есть `--no-beep`. У watch_example флаг `--no-beep` сохранён,
но теперь это поведение по умолчанию; `--beep` включает дополнительный импульс.
`--no-beep` не отключает самостоятельные звуки прошивки.

Сбой LED/пищалки не отменяет успешное чтение или подтверждённую запись:
пример выдаёт отдельное предупреждение. В watch после ошибки индикации её
команды отключаются до перезапуска, а события карт продолжают поступать.

## Чтение и запись в своём приложении

Библиотека не зависит от менеджера или БД. Чтобы выполнить `import wcopy_reader`,
папка `wcopy_reader_package` должна быть доступна в пути поиска модулей Python.
Примеры из `examples/` добавляют её автоматически относительно своего файла,
поэтому запускаются и из другой текущей папки.
Установка `requirements.txt` устанавливает hidapi, но не сам модуль `wcopy_reader`.
В [CyberpunkMasterManager](https://github.com/limbura/CyberpunkMasterManager)
путь к библиотеке задаётся в `config.toml`; менеджер загружает её самостоятельно.
В этой системе число в памяти карты — `main.card_id`, а ID на наклейке — `main.id`.
Библиотека не различает эти понятия и записывает именно переданное число.

```python
from wcopy_reader import read_card_number, write_card_number, set_led, beep, RFIDError

number = read_card_number(auto_feedback=False)
set_led("green")
```

Для записи отделяйте обработку ошибок данных от ошибок индикации:

```python
try:
    actual_id = write_card_number(555, auto_feedback=False)
except RFIDError as error:
    print("Успех записи не подтверждён:", error.code, error.stage, error)
else:
    print("Записано и проверено:", actual_id)
    try:
        beep(t=10)
    except RFIDError as error:
        print("Запись успешна, но сигнал не подтверждён:", error)
```

Запись всегда сначала читает блок, сохраняет байты вне выбранного диапазона,
записывает весь 16-байтовый блок, затем выключает/включает RF-поле, снова ищет
карту, авторизуется и читает блок. Успех возвращается только при совпадении
**UID и всех 16 байт**. Блок 0 с заводским UID и блок ключей не записываются.

Функция возвращает ID из контрольного чтения. Ноль допустим. Диапазон по
умолчанию: **0…18446744073709551615**. Это двоичное число, не строка ASCII
и не MIFARE value block. Параметры формата: `offset=8, length=8, byteorder="big"`.
Они доступны у read_card_number и write_card_number. Неверные аргументы
вызывают ValueError до обращения к считывателю.

При ошибке после отправки команды записи карта уже могла измениться.
Автоматического повтора или отката нет. Проверьте ID через read_example.py.
Держите одну карту на считывателе до завершения операции.

Полные данные доступны через `card = read_card()`:
`card.uid`, `card.block` (16 байт), `card.atqa`, `card.sak`, `card.number`.
Метод `card.to_int(offset=8, length=8, byteorder="big")` задаёт формат числа.

## Наблюдение и индикация в приложении

Без индикации, только новые прочитанные карты и ошибки:

```python
from wcopy_reader import watch_cards, CardPresented

for event in watch_cards():
    if isinstance(event, CardPresented):
        print(event.number, event.uid.hex(" "))
    else:
        print(event.error.code, event.error)
```

Для ручного управления индикацией старого wCopy используйте `report_state=True, auto_feedback=False`:

```python
from wcopy_reader import watch_cards, CardState, CardPresented, set_led, RFIDError

for event in watch_cards(report_state=True, auto_feedback=False):
    if isinstance(event, CardState):
        try:
            set_led("green" if event.present else "red")
            # Если нужен дополнительный звук:
            # if event.is_new:
            #     beep()
        except RFIDError as error:
            print("Ошибка индикации:", error)
    elif isinstance(event, CardPresented):
        print("Новая карта:", event.number)
    else:
        print("Ошибка чтения:", event.error)
```

`CardState` выдаётся после каждого успешного чтения или ответа «нет карты».
`present` учитывает фильтр снятия, `is_new` означает новое успешное чтение,
после которого отдельно следует CardPresented с полными данными.
Пример watch_example повторяет LED на каждом таком событии, как в проверенной
версии: команды чтения и RF-поля могут менять индикацию самостоятельно.
Выбор маски команды и дополнительного звука находится в примере;
реальный цвет на проверенном устройстве выбирает прошивка по наличию карты.

Правила обнаружения не изменились:

- Тот же UID не создаёт нового CardPresented до двух последовательных
  ответов «нет карты» (removal_checks=2) или до чтения другого UID.
- Один пропуск опроса не означает снятие и не включает новый писк.
- Ошибки USB, тайм-ауты и авторизации не считаются снятием карты.
- Повторы одинаковых ошибок подряд подавляются; CardError содержит RFIDError.
- `63 00` на этапе poll трактуется как «карта не обнаружена» для этой прошивки.
  Это может быть неудачный поиск присутствующей карты. Два таких результата
  способны создать ложное повторное прикладывание — ограничение опроса.
- Изменение ID у удерживаемой карты с тем же UID не создаёт нового события.

В `watch_cards` параметр `auto_feedback=True` включает автоматическую индикацию.
Старый параметр `feedback`, если указан, имеет приоритет над auto_feedback.
`sound=False` отключает отдельный писк чтения Cyb, сохраняя обновление LED wCopy;
самостоятельные звуки прошивки остаются. Ручной `set_reader_feedback(color, beep=True)`
использует T=5; для другого T вызывайте `beep(t=...)`. Не дублируйте автоматические
сигналы ручными вызовами.
Обычный watch_cards() по-прежнему выдаёт только CardPresented/CardError.

## Подключение и потоки

`list_readers()` возвращает ReaderInfo: path, product, manufacturer, interface,
backend, vendor_id, product_id. Первые четыре поля и их порядок сохранены.
При нескольких устройствах выберите одно и передавайте его path во все вызовы
чтения, записи и индикации. Без path требуется ровно один подходящий считыватель.
`timeout_ms=2500` ограничивает один HID-ответ, а не длительность всей операции.

Вызовы блокирующие и сериализуются внутри процесса. Чтение/запись/индикацию
в GUI выполняйте в рабочем потоке; передавайте события через очередь.
watch_cards принимает `stop=threading.Event()`: stop.set() завершает цикл
после текущей операции. `interval=0.25` — пауза после опроса/обработки события.
Другие процессы со считывателем одновременно работать не должны.

## Ошибки

Ожидаемые аппаратные ошибки наследуются от RFIDError.
Поля: code, stage, status (если имеется), response (если имеется).
Ветвите логику по классам/code, а не по тексту сообщения.

| Класс | Значение |
|---|---|
| DependencyError | Не загрузился hidapi |
| ReaderNotFoundError / MultipleReadersError | Нет считывателя / требуется выбрать один |
| ReaderOpenError / USBError | Не удалось открыть устройство / ошибка обмена |
| ReaderTimeoutError | Нет ответа в срок |
| ProtocolError / ReaderCommandError | Повреждённый ответ / ошибка команды |
| NoCardError / UnsupportedCardError | Карта не найдена / неподдерживаемый тип |
| AuthenticationError / CardReadError | Ошибка авторизации / чтения |
| CardWriteError | Команда записи вернула ошибку |
| VerificationError | После записи не подтверждены UID и весь блок |
| FeedbackError | Неожиданный ответ команды индикации |

При VerificationError исходная ошибка повторного чтения доступна через
`error.__cause__`, если она была. Сбой авторизации не доказывает неверный ключ:
причиной может быть снятие карты или плохая связь.

## Версия 1.4.2: диагностика индикации

Основа — версия 1.4.1 со структурой папок пользователя. Добавлен только
диагностический скрипт и это описание; поведение функций библиотеки и примеров
не менялось. Экспериментальные локальные правки write_example в эту сборку не входят.

Запустите кнопкой VS Code файл `tests_and_other/indication_diagnostics.py` или
из папки `wcopy_reader_package`:

```powershell
.\.venv\Scripts\python.exe .\tests_and_other\indication_diagnostics.py
```

Начните с пункта **1**. Скрипт ведёт по семи режимам. Перед каждым режимом
переподключите USB по инструкции, затем следуйте фазам: карта отсутствует,
приложить и держать, убрать. После опыта впишите реальные цвет и звук.
Не считайте одинаковый ответ `90 01` доказательством физического эффекта.

| Режим | Действие после каждого опроса |
|---|---|
| A | Ничего, как watch с --no-feedback |
| B | red/green по наличию карты, как штатный watch без отдельного beep |
| C | Открыть и закрыть HID, не отправляя команд |
| D | Только задержка: медианное время дополнительного действия из B |
| E | Всегда команда red |
| F | Всегда команда green |
| G | Всегда команда off |

Во всех режимах одинаковый порядок чтения и интервал 0.25 с после действий.
Две проверки отсутствия подряд снимают состояние «карта есть», как в watch.
Тайм-ауты, ошибки авторизации и другие ошибки прекращают опыт, а не трактуются
как снятие карты. Команда цвета в диагностике передаётся с сохранением сырого
ответа без предположений о его семантике. Нет автоматической записи карты.

Результаты помогают разделить причины, но один прогон не доказывает механизм
прошивки. Если эффект даёт C, важно открытие/закрытие HID. Если только D —
возможно влияние времени; медиана приближённая, нужна повторная проверка.
Если B/E/F/G работают, а A/C/D нет, влияние связано с обменом FF0040.
Если E/F/G задают реальный цвет независимо от карты — маски управления работают.
Если поведение одинаковое для разных масок и следует наличию карты — возможен
побочный эффект команды или включение автоматического режима.

Пункт **2** сравнивает одиночные команды red, green, off, red в четырёх условиях:
после USB без INIT, после INIT без чтения, после чтения в том же HID-сеансе,
после чтения в новом HID-сеансе. После каждого опыта также проверяется
прикладывание/снятие карты без дальнейших команд от программы.

Пункт **3** меняет только параметр T в команде писка: 1, 3, 5, 10.
Перед серией выполняется чтение; каждый писк отправляется в новом HID-сеансе,
как публичный beep(). Карта остаётся неподвижной. Единицы T неизвестны;
не приравнивайте число к миллисекундам. Возможное изменение LED тоже отметьте.
Тест после чтения не заменяет окончательную проверку после реальной записи.

Журнал USB-пакетов `.log` и ответы пользователя `.json` автоматически сохраняются
в `diagnostics_logs` рядом с библиотекой. Пришлите оба файла одного запуска.
Можно закончить после группы 1 и обсудить результат, остальные пункты необязательны
до анализа. Для выхода используйте q; Ctrl+C завершает скрипт с сохранением данных.

## Версия 1.4.4: проверка выбранной карты до записи

В `write_card_number()` добавлены необязательные аргументы `expected_uid` (bytes,
4 или 7 байт) и `expected_block` (bytes, 16 байт). Они сравниваются с начальным
чтением **внутри того же сеанса до команды записи**. При несовпадении вызывается
`VerificationError` с `stage="prewrite"`; команда записи не отправляется.
Некорректный формат аргументов вызывает ValueError до открытия USB.

```python
from wcopy_reader import read_card, write_card_number

card = read_card()
# Здесь приложение проверяет карту и получает подтверждение пользователя.
write_card_number(555, expected_uid=card.uid, expected_block=card.block)
```

Это используется в пакетном режиме CyberpunkMasterManager. Без этих аргументов
старые вызовы работают по-прежнему. Проверка UID и всего блока после записи
сохранена. UID не является защитой от клонирования: физические карты с одинаковыми
UID и содержимым библиотека различить не может.
