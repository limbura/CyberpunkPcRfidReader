# CyberpunkPcRfidReader — библиотека работы с RFID-картами

`wcopy_reader` — Python-модуль для чтения и записи игрового `card_id` на картах **MIFARE Classic** через USB HID-считыватель. Он поддерживает **два семейства считывателей**, самостоятельно определяет подключённую модель и использует нужный протокол. При замене одного поддерживаемого считывателя другим код приложения менять не нужно.

Библиотека рассчитана на **определённый формат хранения игрового ID**, а не на произвольное чтение всех данных карты: она работает с **блоком 1 сектора 0**, стандартным ключом A `FF FF FF FF FF FF` и двоичным целым числом в выбранной части этого блока.

## Поддерживаемые считыватели и автоматический выбор

| Семейство | USB VID:PID | Чтение карты | Запись карты |
|---|---|---|---|
| **wCopy** — PMX-V624-C / NSR109-HIDIC V806N (nfcPro) | `2518:6018` | PN-совместимые команды: поиск UID, авторизация, чтение блока 1 | Авторизация, запись блока 1, контрольное чтение |
| **Cyb** — TCC-TSY-TBY (Cyb_Nfctool) | `0483:4300`, `0483:4343` | Одна команда `0x6C` для блоков 0 и 1 | Отдельные запросы `0x69` и `0x6C` до/после записи `0x6A` |

Для Cyb библиотека дополнительно проверяет USB-строки производителя (фрагмент `CYBDZKJ-BSJ`), продукта (`TCC-TSY-TBY`) и серийного номера (`BEGIN-2025`). Одного VID:PID недостаточно, чтобы считать произвольное устройство подходящим.

При вызове `read_card()`, `read_card_number()` или `write_card_number()` библиотека перечисляет поддерживаемые устройства и выбирает протокол по их признакам:

- Если найден **ровно один** поддерживаемый считыватель, выбор происходит автоматически.
- Если их несколько, возникает `MultipleReadersError`: укажите конкретный `path` из `list_readers()` во всех вызовах.
- Если подходящих устройств нет, возникает `ReaderNotFoundError`. Неподдерживаемые модели автоматически не выбираются.

Не запускайте параллельно nfcPro, Cyb_Nfctool или другое приложение, использующее тот же HID-интерфейс.

## Установка и запуск

Требуется Python с поддержкой аннотаций используемого модуля (рекомендуется **Python 3.11+**) и зависимость `hidapi==0.15.0`. Примеры ниже выполняются из **корня репозитория**:

```powershell
python -m pip install -r wcopy_reader_package/requirements.txt
python wcopy_reader_package/examples/read_example.py
```

Модуль находится в файле `wcopy_reader_package/wcopy_reader.py`. Это **обычный Python-файл**, а не пакет с `__init__.py`. При запуске своих скриптов добавьте каталог `wcopy_reader_package` в путь импорта (например, запускайте скрипт из этого каталога или настройте `PYTHONPATH`). Импорт в коде одинаков для обоих считывателей:

```python
from wcopy_reader import read_card, read_card_number, write_card_number
```

Отдельные USB-драйверы/права доступа должны позволять `hidapi` открыть устройство в используемой ОС.

## Где хранится card_id

В MIFARE Classic память делится на секторы и 16-байтовые блоки. Для поддерживаемого формата используется **сектор 0**:

| Блок | Назначение для библиотеки |
|---|---|
| **0** | Данные производителя, в том числе UID; Cyb читает его для быстрого получения UID, но **не записывает** |
| **1** | **Единственный пользовательский блок, который библиотека читает и записывает**; здесь хранится игровой `card_id` |
| 2 | Библиотекой не используется |
| 3 | Sector trailer: ключи и права доступа; библиотекой не записывается |

По умолчанию число лежит в **байтах 8–15 блока 1**: беззнаковый `uint64`, **big-endian**, диапазон `0`…`18446744073709551615`. Это именно двоичное представление целого, **не текстовые ASCII-цифры** и не MIFARE value block. Например, число `513` занимает последние восемь байтов как `00 00 00 00 00 00 02 01`.

Можно указать `offset`, `length` и `byteorder`, чтобы извлечь или записать число **в другой части того же блока 1**: `offset >= 0`, `length >= 1`, `offset + length <= 16`, порядок байтов `"big"` или `"little"`. **Нельзя** выбрать другой блок, сектор или произвольный ключ, прочитать NDEF, автоматически найти ID в памяти либо читать/писать весь дамп карты. Формат хранения должен совпадать с форматом, в котором приложение записало ID.

## Чтение

```python
from wcopy_reader import read_card, read_card_number, NoCardError, RFIDError

try:
    card = read_card()  # Карта уже должна находиться на антенне.
    print("UID:", card.uid.hex(" ").upper())
    print("card_id:", card.number)
    print("Блок 1:", card.block.hex(" "))
    print("Новое прикладывание:", card.is_new, card.presentation_id)
except NoCardError:
    print("Карта не обнаружена или недоступна для чтения")
except RFIDError as error:
    print("Ошибка:", error.code, error.stage, error)

# Если нужен только игровой ID:
# card_id = read_card_number()
# Другое расположение числа, но всё равно внутри блока 1:
# card_id = read_card_number(offset=12, length=4, byteorder="little")
```

`read_card()` возвращает неизменяемый объект `CardData`:

| Поле/свойство | Значение |
|---|---|
| `uid: bytes` | UID карты (для быстрого Cyb — первые четыре байта блока 0) |
| `block: bytes` | Ровно 16 байт блока 1 |
| `number: int` | Число из байтов 8–15 блока 1, big-endian |
| `to_int(offset=8, length=8, byteorder="big")` | Число из выбранной части блока 1 |
| `atqa: bytes`, `sak: int` | RF-параметры для wCopy; у **быстрого чтения Cyb** не определяются (подробности ниже) |
| `is_new: bool` | Первый успешный опрос после нового прикладывания/смены UID |
| `presentation_id: int` | Уникальный в рамках процесса номер прикладывания, сохраняемый при удержании карты |

`read_card_number()` возвращает только `int`. Оба метода принимают `path=None`, `timeout_ms=2500` и `auto_feedback=True`. Тайм-аут ограничивает ожидание **одного ответа HID**, а не всей операции. Внутри одного процесса операции сериализуются.

### Быстрое чтение Cyb: совместимость и ограничения

При обычном чтении Cyb отправляется **один запрос `0x6C(start=0, count=2)`** с ключами `FF FF FF FF FF FF`, без отдельной команды поиска UID `0x69`. Ожидается маска успеха `0x00000003` и **32 байта**: блок 0 + блок 1.

Библиотека берёт `uid = block0[0:4]` и проверяет `block0[4] == UID0 XOR UID1 XOR UID2 XOR UID3` (BCC); игровой ID извлекается из блока 1.

**Это не универсальное чтение UID, и подходит не любая карта:**

- Быстрый метод рассчитан на **обычные MIFARE Classic с постоянным 4-байтовым UID**, у которых заводской блок 0 содержит соответствующий UID и корректный BCC. Для чтения сектора 0 должен подходить используемый ключ A `FF FF FF FF FF FF` и настройки доступа.
- **7-байтовые UID, случайные RID, нестандартные карты, некоторые UID-changeable/«magic»-карты и нетипичная структура блока 0 не поддерживаются надёжно.** Проверка BCC обнаруживает многие несовместимые структуры, **но не определяет фактическую длину UID** и не гарантирует отказ для любой неподходящей карты: возможны случайные совпадения.
- UID берётся **из памяти**, а не из результата радиочастотной антиколлизии. На нестандартной/изменяемой карте он может **не совпасть** с UID, который сообщила бы `0x69`. Наличие правильного BCC не доказывает совпадение и **не подтверждает подлинность** карты. UID вообще не является криптографической защитой от клонирования.
- При обычном быстром чтении у Cyb в `CardData` установлены **`atqa=b"\x00\x00"` и `sak=0`** — это условные значения «не получены», **не настоящие ATQA/SAK**. Если приложению нужны измеренные ATQA/SAK, быстрый путь Cyb их не предоставляет.
- Маска `0` в ответе `0x6C` трактуется как `NoCardError` для удобства опроса. **Считыватель не различает** этим результатом отсутствие карты, неподходящий ключ/права доступа и некоторые ошибки RF. Два таких ответа могут ошибочно считаться снятием недоступной карты; это важно для `is_new` и `watch_cards()`. Частично успешное чтение вызывает `CardReadError`.
- Два блока приходят в **одном HID-ответе**, но прошивка не гарантирует атомарности RF-операции при физической замене карты прямо во время чтения.

Поэтому для игры используйте **однотипные предварительно проверенные карты** с правильным форматом. Если требуется работа с произвольными MIFARE-картами, настоящими ATQA/SAK или надёжное подтверждение физического UID, текущий быстрый путь Cyb для этого не предназначен.

У **wCopy** UID и параметры карты получаются при обычном поиске, до авторизации, без предположения о структуре блока 0. Поддерживаются UID длиной 4 или 7 байт при подходящем типе MIFARE Classic и доступном ключе сектора.

## Запись card_id

```python
from wcopy_reader import read_card, write_card_number, RFIDError

# Считайте нужную карту и убедитесь, что записывать будете именно её:
card = read_card()

try:
    verified = write_card_number(
        123456789,
        expected_uid=card.uid,
        expected_block=card.block,
    )
    print("Записано и проверено:", verified)
except RFIDError as error:
    print("Результат записи не подтверждён:", error.code, error.stage)
```

`write_card_number(number)` изменяет по умолчанию **только байты 8–15 блока 1**, сохраняя остальные байты. При пользовательских `offset`, `length` и `byteorder` изменяется выбранный диапазон в пределах того же блока. Физически записывается весь 16-байтовый блок.

Перед записью библиотека читает текущие UID и блок. Необязательные `expected_uid` (4 или 7 байт) и `expected_block` (16 байт) проверяются **перед отправкой команды записи**; при несовпадении возникает `VerificationError(stage="prewrite")`, запись не выполняется. После записи заново читаются UID и **все 16 байт**; только совпадение подтверждает успех.

Для **Cyb запись намеренно использует отдельную процедуру**: `0x69 → 0x6C(1,1) → 0x6A → 0x69 → 0x6C(1,1)`. Она не заменена быстрым чтением блока 0 и сохраняет проверку UID при записи. Для **wCopy** используется свой прежний путь авторизации, записи и контрольного чтения.

**Не убирайте карту до окончания операции.** Если после отправки команды записи возник тайм-аут, ошибка USB или `VerificationError`, данные **уже могли измениться**: библиотека не повторяет запись автоматически и не делает откат. Перед повторной попыткой отдельно прочитайте карту. Блок производителя (0), ключи и права доступа (sector trailer) не изменяются.

## Постоянное наблюдение за картами

```python
from wcopy_reader import watch_cards, CardPresented, CardError, CardState

for event in watch_cards(interval=0.25, removal_checks=2, report_state=True):
    if isinstance(event, CardPresented):
        print("Приложена карта", event.number, event.uid.hex())
    elif isinstance(event, CardError):
        print("Ошибка чтения:", event.error.code, event.error.stage)
    elif isinstance(event, CardState):
        print("Карта присутствует:", event.present)
```

`watch_cards()` повторяет чтение с паузой `interval` между опросами. По умолчанию возвращает **только** `CardPresented` и `CardError`; при `report_state=True` дополнительно выдаёт `CardState` после успешного опроса или ответа «нет карты».

- Повтор одного UID при непрерывном удержании не создаёт новых событий `CardPresented`. Другой UID считается новой картой.
- По умолчанию два последовательных ответа `NoCardError` позволяют считать карту снятой и повторное прикладывание новой картой. Один пропуск не должен делать этого. Ошибки USB и тайм-ауты не считаются снятием.
- `is_card_removed()` проверяет накопленное библиотекой состояние и **не отправляет USB-запрос**; оно становится истинным после двух подтверждённых библиотекой отсутствий.
- `watch_cards(stop=threading.Event())` можно остановить через `stop.set()`; завершение произойдёт после текущего опроса. Для графического интерфейса запускайте блокирующие операции в рабочем потоке.
- `sound=False` отключает отдельный автоматический писк Cyb, но не обязательно звуки прошивки. `auto_feedback=False` отключает дополнительную автоматическую индикацию при вызовах библиотеки.

У Cyb «отсутствие» при маске `0` может также означать недоступность сектора (см. ограничения выше). При выборе `removal_checks` учитывайте ложные пропуски и продолжительность цикла опроса.

## Звук, светодиод и управление Cyb

По умолчанию `auto_feedback=True`:

| Событие | Cyb | wCopy |
|---|---|---|
| Новое успешно прочитанное прикладывание | Один короткий сигнал | Обновление LED |
| Удерживаемая карта | Без нового автоматического сигнала | Обновление LED |
| Нет карты | Без нового сигнала | Обновление LED |
| Успешная запись и проверка | Два коротких сигнала | LED и один сигнал |

Ручные функции: `beep(t=5, count=1)`, `set_led("red" | "green" | "off")`, `set_reader_feedback(color, beep=False, count=1)`. Они также принимают `path` и `timeout_ms`. Параметр `t` — **параметр команды**, не миллисекунды; `count` у Cyb ограничен 255, а wCopy подаёт один сигнал независимо от `count`. Физический цвет LED при вызове `set_led` не гарантирован: он зависит от прошивки; на Cyb `red` и `green` отправляют одну и ту же команду красного LED. Не дублируйте автоматические сигналы ручными без необходимости.

Cyb по умолчанию удерживает режим управления с ПК между операциями (но открывает и закрывает USB-дескриптор при каждом вызове), чтобы избежать лишнего автономного писка. Используйте `close_readers()` **после остановки опроса**, чтобы вернуть автономный режим; функция также зарегистрирована через `atexit`. Если процесс был аварийно завершён, может потребоваться физически переподключить USB. `set_persistent_host_control(False)` отключает удержание этого режима; на старый wCopy эта настройка не влияет.

## Ошибки и ограничения выполнения

Аппаратные ошибки наследуются от `RFIDError` и имеют поля `code`, `stage`, а при наличии — `status` и `response`:

| Ошибка | Что означает |
|---|---|
| `ReaderNotFoundError` / `MultipleReadersError` | Нет подходящего считывателя / их несколько |
| `ReaderOpenError`, `USBError`, `ReaderTimeoutError` | Проблема открытия, обмена или ожидания ответа |
| `NoCardError` | Карта не найдена **или** недоступна при быстром чтении Cyb |
| `UnsupportedCardError` | Неподдерживаемый формат карты/UID |
| `AuthenticationError`, `CardReadError` | Не прошла авторизация / чтение |
| `ProtocolError`, `ReaderCommandError` | Неожиданный пакет или ошибка команды |
| `CardWriteError`, `VerificationError` | Ошибка записи или её проверки |
| `DependencyError`, `FeedbackError` | Зависимость HID или индикация |

Неверные значения аргументов вызывают `ValueError`. Ошибки аппаратного доступа не означают, что карта обязательно повреждена или что запись не состоялась. `read_card()`, `write_card_number()` и наблюдение **блокирующие**; в пределах процесса операции синхронизируются одной блокировкой. Не используйте один HID-считыватель одновременно из нескольких процессов.

Тесты используют имитацию HID-считывателей; реальное USB-устройство для них не требуется. ## Автоматическое создание GitHub Release

Workflow [release.yml](.github/workflows/release.yml) запускается при отправке нового тега вида **`vX.Y.Z`**. Тег должен совпадать с константой `__version__` в `wcopy_reader_package/wcopy_reader.py`, а помеченный коммит должен принадлежать истории `master`. Несовпадение останавливает выпуск.

Перед публикацией выполняются тесты и проверка синтаксиса на **Ubuntu / Python 3.11** и **Windows / Python 3.13**. Только после их успешного завершения создаётся GitHub Release с автоматически сформированными заметками и двумя вложениями:

- `wcopy_reader_package_vX.Y.Z.zip` — библиотека `wcopy_reader.py`, `requirements.txt`, актуальный README, описание обоих протоколов и три примера из `examples/`. Внутри ZIP сохраняется каталог `wcopy_reader_package_vX.Y.Z/`.
- `wcopy_reader_package_vX.Y.Z.sha256` — контрольная сумма архива.

Архив **не содержит** оригинальные сторонние EXE, низкоуровневые утилиты, тесты или диагностические журналы. Это исходный Python-модуль с зависимостью `hidapi`, а не автономный Windows EXE.

Для выпуска новой версии обновите `__version__` в исходном файле и отправьте тег из актуального `master`:

```powershell
git switch master
git pull --ff-only origin master
git tag v1.8.0
git push origin v1.8.0
```

В примере указан тег для версии `1.8.0`; для следующего выпуска используйте соответствующий **новый** номер версии. Создавать тег, который уже существует, повторно не нужно. Публикация начинается только после отправки тега; обычный push в `master` релиз не создаёт.

Локально проверить состав архива (без публикации) можно так:

```powershell
python scripts/build_release.py --tag v1.8.0
```

Готовые файлы появятся в каталоге `dist/`. Для создания GitHub Release локальный запуск не требуется.
